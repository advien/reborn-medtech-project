## Фаза B — ML на открытых данных → статья `drift_personalization`

- [x] **B0.** Слой данных: `reborn/data/` (загрузчики, конвейер, протоколы, тесты)
- [x] **B1.** Ninapro DB6, испытуемые s01–s02 (20 сессий, 4.1 ГБ) → `data/ninapro_db6/`
- [x] **B2.** Проверено на реальных файлах: шаблон имён совпал; пороги откалиброваны →
      [`experiments/configs/ninapro_db6_qc.json`](../../experiments/configs/ninapro_db6_qc.json).
      Три находки: колонки 8–9 — паддинг; `flatline_std` тоже абсолютный и его надо выводить;
      `corruption.py` тоже в абсолютных амплитудах, иначе детекция меряет масштаб, а не детектор
- [x] **B3.** Notebook 01 исполнен на реальных окнах s01 (10 сессий, 136 234 окна).
      QC-отбраковка **0.67%**, причина — `dropout`; сессия `d04_t01` 3.57% (13.5× медианы) —
      сигнальное событие, а не шум. Детекция масштабированных инъекций: dropout/saturation/
      clipping/baseline_offset 100%. **Находка:** advisory-детектор (rms/mav/zcr + Махаланобис)
      на реальных данных ловит только baseline_offset (100%), а `noise_burst` — 2.8% (ниже clean
      4.4%). Три time-domain фичи ему не дают тяги; нужен богаче признак (частотный) прежде чем
      advisory-слой оправдает себя. → отдельный пункт B3a.
- [x] **B3a.** `anomaly_features` = Hudgins + спектральные (mean-freq, HF-ratio) + импульсные
      (kurtosis, crest, sub-window RMS). На реальном s01: saturation/clipping 16%/9% → **100%**,
      noise_burst (severity 3) 2.8% → **~34%** (выше clean). Sweep по энергии: sev1≈clean,
      sev3 41%, sev5 75–96%, sev8 ~100% — детекция есть **выше энергетического порога**, короткий
      слабый всплеск на уровне окна неотличим от вариации EMG. **Остаток:** clean false-positive
      вырос 4.4% → 8.8% (10 признаков на ~250 окнах обучения) → B3b.
- [x] **B3b.** Калибровка порога на **отдельном** held-out clean-наборе (`AnomalyDetector.fit(...,
      calibration=...)`) + fit на 2000 окнах: clean FP 8.8% → **5.0%** (time-ordered) / **2.8%**
      (shuffled control). Разрыв 5.0% vs 2.8% = **внутрисессионный дрейф** (порог с раннего сегмента
      недокрывает поздний) — не ошибка детектора, а тот самый дрейф из фазы 03. noise_burst теперь
      честные 17% (было 33.6% из-за завышенного порога). → открыл B3c.
- [x] **B3c.** Пер-сессионный адаптивный порог измерен (notebook 03): benign-FP mean 5.3% → **2.6%**
      (к цели, дисперсия срезана), degraded d04 остаётся 4.2% — **не маскируется**, а торчит контрастнее.
      **Вердикт: помогает.** Принцип: адаптируется только advisory-порог, детерминированный QC — фиксированный
      floor (safety authoritative). → B3c-impl.
- [x] **B3c-impl.** `reborn.ml.anomaly.AdaptiveThreshold` — пер-сессионная/rolling адаптация
      advisory-порога (reset/update/flags) + `AnomalyDetector.distance()` (порог = отделимая политика).
      Строго advisory, кормится **только** окнами, прошедшими детерминированный floor (тест это
      фиксирует). Notebook 03 теперь считает вердикт через этот же класс — числа совпали 1:1. Тесты:
      warmup-fallback, reset, удержание FP под дрейфом, floor-authoritative. Линия B3 закрыта.
- [x] **B4.** Notebook 02 исполнен (s01–s02, 4 протокола × {binary,multi} × {LDA,logreg}), числа
      воспроизвелись 1:1. **Стоп-правило НЕ срабатывает, но переформулирует историю:** binary (решение
      Reborn) почти не дрейфует по точности (−0.021) и дрейф **эпизодический** (сессия elapsed=3
      проваливается до 0.756, остальное плоско), multi — сильно (−0.109). Главное: **калибровка (ECE)
      деградирует быстрее точности** (×1.7–3.6) — модель становится увереннее, чем заслуживает →
      прямая связка с architecture-paper. Cross-subject для binary НЕ худший случай (0.912) → мало
      headroom для few-shot. Записано: `findings-intent-drift.md`. → notebook 03 = эпизодическая
      деградация, не медленный дрейф.
- [x] **B4a.** Коллапс `elapsed=3` разобран (notebook 03): это **один** сплит — s02/`d02_t02`
      (bal 0.641, ECE 0.187), и это **не** QC-деградировавшая d04. Advisory-детектор его НЕ выделяет
      (anom ch0 0.5% — минимум; сессии с нормальной точностью аномальнее). Оба класса рушатся при
      conf 0.79 → **concept drift** (P(y|x)), невидимый для QC и anomaly-детектора (оба — модели P(x)).
      **Вывод для архитектуры:** мониторинг сигнала ≠ мониторинг решения; нужен монитор уверенности/
      рассогласования, а не ещё один input-слой. → мотивирует B5/decision-monitor.
- [x] **B4b (decision-monitor).** Монитор решения ловит concept drift, невидимый input-слоям
      (notebook 03): на s02/d02_t02 mean conf 0.79 (др. 0.92–0.95), **model disagreement 22%** (др.
      3–7%, ~4×), move-pred 54% (train 72%) — а anomaly-детектор там 0.5% (минимум). **История B3+B4
      замкнута:** input-мониторинг (P(x)) и decision-мониторинг (P(y|x)) — комплементарны, каждый
      ловит свой отказ DB6. Итог: `synthesis-two-monitors.md`. Per-window gate недостаточен → нужен
      session-level distributional монитор.

### Итог линий B3+B4
Два независимых монитора дрейфа — **вход** (качество сигнала) и **решение** (дрейф границы) — как
раздельные safety-слои. Эмпирическая база для architecture-paper готова
([`synthesis-two-monitors.md`](../../papers/drift_personalization/synthesis-two-monitors.md)).
Дальше: few-shot (B6/B7) — чинит ли рекалибровка concept drift и что быстрее восстанавливается,
калибровка или точность; проводка decision-монитора в `reborn.decision` — фаза C.
